## 部署体系改造：GitHub Actions 前后端分离自动部署

### 需求（用户明确 5 条）

1. 通过 GitHub Actions 自动部署
2. 前端后端分开
3. MySQL / Redis 等由外部提供，**不用 Docker Compose**
4. 前端不用 Docker，只需编写给前端用的 nginx 文件
5. 后端用 Docker 部署

### 关键决策（已与用户确认）

| 决策点 | 结论 |
| --- | --- |
| 镜像仓库 | `ghcr.io/<owner>/rollin-backend` |
| 部署通道 | SSH 直连（原生 ssh/scp，未引入 appleboy 等第三方 action） |
| 域名 | 双域名（t.xxx 候选人 / admin.xxx 管理），保留 nginx 白名单隔离 |
| 后端运行方式 | 纯 `docker run` + 部署脚本，彻底不用 compose |

### 发现并修掉的既有缺陷

- **迁移命令写法错误**（原 README / 两份 compose / deploy 文档中广泛存在）：
  `docker compose run --rm backend /app/rollin-server migrate up` 会把二进制路径当成
  `os.Args[1]`，`main()` 判 `args[0] == "migrate"` 失败 → 进程被当成「启动服务」。
  镜像 ENTRYPOINT 已是 `/app/rollin-server`，正确写法是只传子命令 `migrate up`。
  已修正 README、`docker-compose.dev.yml` 注释，并在 `docker-compose.legacy.yml`、
  新部署脚本中加了说明。
- `nginx -t` 会读取 certbot 证书（`/etc/letsencrypt/live/*/privkey.pem` 仅 root 可读），
  非 root 执行必然 Permission denied。因此前端脚本把 `nginx -t` 提到改动之前做前置校验，
  并在报错里提示设置 `DEPLOY_SUDO=sudo`；否则一次正常发布会被误判失败并回滚。

### 约定与前提

- 服务器上 `/etc/rollin/backend.env`（600）是唯一存放真实凭证的地方，不进 git、不进流水线。
- `/opt/rollin/releases/<sha>` 存前端产物，`/var/www/rollin/current` 是指向它的符号链接。
- 后端端口只绑 `127.0.0.1:8080`；域名隔离完全由宿主机 nginx 白名单实现。
- 迁移先于换容器执行；迁移不支持自动降级，代码回滚不回退 schema。
- 仓库尚无 git：需要用户自行 `git init` + 推到 GitHub 后流水线才能跑。
